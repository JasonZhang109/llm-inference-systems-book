## 已知的可信度边界

以下几处需要在引用时特别小心，已同步写入对应章节正文：

1. **产品页规格是标称值**。GB300 NVL72 与 MI350 的带宽、算力均为厂商峰值理论值，
   厂商脚注明确"服务器厂商配置不同，结果可能不同"。它们只能作为上界参照。
2. **NIXL 的 README 页未给出版本号**，也未声明与 vLLM / SGLang / TensorRT-LLM / LMCache 的集成，
   因此相关集成关系在正文中只从各引擎一侧确认，不从 NIXL 侧推断。
3. **OpenTelemetry GenAI 语义约定整体为 Development 级**，无任何稳定级 GenAI 指标，
   且官方注明"初始版本，后续可能新增"。跨版本升级须预期破坏性变更。
4. **msprof 与 HCCL 的官网正文为前端渲染页面**，本次以 CANN oam-tools 仓库源码与文档口径为准，
   正文已注明"不同 CANN 版本与硬件型号下的实际支持情况须以运行环境的 `msprof --help` 为准"。
5. **vLLM 发布说明未覆盖调度参数**。两版发布说明均未出现 chunked prefill、`max_num_batched_tokens`、
   调度策略或优先级参数，因此正文明确声明这些参数的状态不能由发布说明推出。
6. **AI Perf 的 TTFO 是工具定义的指标名**，不是引擎内既有指标。vLLM 中不存在 TTFO，
   最接近的是 `vllm:inter_token_latency_seconds`。跨工具比较必须对齐口径。
